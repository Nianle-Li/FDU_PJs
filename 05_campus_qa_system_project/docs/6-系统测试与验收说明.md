## 七、数据库一致性验证

完整导入与查询验证流程见 [5-数据库导入与查询说明.md](5-数据库导入与查询说明.md)，此处汇总核心验证目标。

### 1. 初始化脚本验证

```bash
createdb fcqa
psql -v ON_ERROR_STOP=1 -d fcqa -f db/init.sql
```

验证目标：

- 扩展（`pg_trgm`、`unaccent`）、14 张表和相关索引能按依赖顺序创建，无错误中断。
- 初始 SQL 种子数据完整导入（8 用户、4 校区、7 建筑、9 设施、6 课程、5 活动等）。
- 重复执行不因主键冲突中断（种子数据使用 `ON CONFLICT DO NOTHING`）。

### 2. SQL 验收脚本验证

```bash
psql -v ON_ERROR_STOP=1 -d fcqa -f db/verify_basic_queries.sql
```

验证目标：

- 表数据量与预期一致。
- 校区 → 建筑 → 设施层级关联查询正常。
- 教师 → 课程 → 排课时间的多表 JOIN 正常。
- 活动 → 设施 → 建筑 → 校区关联查询正常。
- 建筑分类统计、热门查询类别统计、热门活动参与统计正常。
- 事务内写入并回滚，数据库写入能力验证通过。

### 3. 约束与索引验证

- **外键 `ON DELETE RESTRICT`**：删除仍被设施引用的建筑、被活动引用的设施，数据库正确拒绝。
- **外键 `ON DELETE CASCADE`**：删除活动时，`user_activity` 从属记录自动清除。
- **`UNIQUE` 约束**：重复建筑名（同校区）、重复设施名（同建筑）正确触发唯一性错误。
- **`CHECK` 约束**：活动结束时间早于开始时间时，数据库层拒绝插入。
- **`pg_trgm` 索引**：模糊关键词查询在大规模 CSV 数据下性能正常。

## 八、人工功能核查清单

以下各项已在 Demo 模式和 PostgreSQL 模式下分别完成验证：

**用户端**

1. 打开 `http://127.0.0.1:8000`，确认右上角健康状态显示正常。
2. 在"自然语言问答"中输入"邯郸校区有哪些教学楼？"，确认意图识别、SQL 和结果表格正常。
3. 在"自然语言问答"中输入"李芳老师教什么课？"，确认多表 JOIN 结果正确。
4. 在"近期活动"中按校区筛选，确认筛选结果准确。
5. 点击"预约活动"并确认出现在"我的行程"中；再次预约同一活动不产生重复记录。
6. 在"我的行程"中取消预约，确认记录从列表消失。
7. 在"校园速览"中切换查询对象（建筑/设施/课程/活动），确认各类数据正常返回。

**管理员端** 8. 进入"查询工作台"，传统查询模式查询校区，确认 4 个校区信息完整。9. 切换自然语言查询，输入"李芳老师教什么课？"，确认 SQL 文本、识别意图和结果同步展示。10. 进入"数据浏览"，依次查看历史查询、热门查询、热门活动、活动参与和数据表，确认数据展示正常。11. 进入"数据维护"，新增建筑，确认立即可在查询中检索到。12. 编辑刚新增的建筑，修改类型后保存，确认修改结果立即生效。13. 新增设施并绑定到该建筑，确认建筑下拉枚举正确。14. 新增活动并绑定到该设施，确认时间选择器可正常填写。15. 删除演示中新增的活动、设施、建筑，确认数据清理完毕；尝试删除有依赖的建筑，确认约束正确拒绝。

## 九、验收结论

系统在 Demo 模式和 PostgreSQL 正式模式下均通过全部自动化测试与人工核查：

- 前后端与数据库三端完整联动，具备建筑、设施、活动的新增、查询、修改、删除核心 CRUD 能力。
- 自然语言查询可将中文问句解析为 SQL 并返回结构化结果，覆盖建筑、设施、课程、活动、统计等意图类别。
- 关键 SQL 查询（多表 JOIN、分组统计、聚合分析）均在页面上实际执行并展示结果。
- 数据库约束（外键、唯一性、非空检查、CHECK）在增删改操作中正确生效。
- Docker Compose 一键部署验证通过，支持无本地环境依赖的演示。
